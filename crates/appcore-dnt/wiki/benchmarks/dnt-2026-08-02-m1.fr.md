# Benchmark DNT : Apple M1, 2026-08-02

Statut : preuve locale observee pour l'ascendance du commit au moment de
l'execution. Il ne s'agit pas d'une certification multiplateforme et le test
doit etre regenere sur le materiel du deploiement.

## Environnement

- Commande : `cargo run --release -p appcore-dnt --example compare`.
- Materiel : MacBook Pro `MacBookPro17,1`, Apple M1, 8 coeurs, 16 Go de RAM.
- Systeme/kernel : macOS, Darwin 27.0.0, aarch64.
- Stockage : stockage interne SSD, APFS.
- Alimentation : secteur, batterie chargee.
- Rust : `rustc 1.97.1 (8bab26f4f 2026-07-14)`.
- Cargo : profil release, features par defaut.
- Execution : un thread ; 20 operations de prechauffage pour chaque chemin.
- Echantillons : 200 pour read/open ; 100 pour seal/rekey.
- Cache de lecture : chaud. Les resultats ne mesurent ni les I/O durables ni un cache froid.
- Temps CPU, pic RSS et allocations par operation : non mesures.

Le debit ci-dessous utilise les octets semantiques du plaintext. Le debit du
mode compact represente donc le payload utile retourne, et non les octets
chiffres lus sur le disque.

## Interpretation

La lecture plaintext est uniquement une base de comparaison des performances.
Elle ne fournit ni confidentialite, ni authenticite AEAD, ni metadata de
routage authentifiee, ni liaison application/tenant, ni rotation de cle, ni
migration versionnee de DNT.

Le JSON compact a ete plus rapide que le DNT normal pendant cette execution,
car la compression a reduit les octets traites par XChaCha20-Poly1305 et le
digest avec cle d'environ 1 MiB a environ 4 KiB. La decompression a coute moins
cher que l'authentification du ciphertext supplementaire. Cela depend des
donnees et ne constitue pas une garantie generale de compression : le binaire
incompressible est devenu legerement plus grand et plus lent, tandis que le
petit secret n'a subi que l'overhead du wrapper.

Le DNT normal reste le mode par defaut. Le mode compact n'est approprie
qu'apres evaluation de l'entropie du payload, de la fuite de taille et des
limites de decompression. Le p95 de l'open normal V1 pour 1 MiB, mesure a
5,80 ms sur cette machine, est inferieur a la cible desktop initiale de 10 ms,
mais aucune conclusion n'est tiree pour Raspberry Pi, Windows, Linux, stockage
froid, concurrence ou I/O durables.
