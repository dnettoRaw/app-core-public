The optional appcore-ui feature native-input-timing adds local event timing without changing UiNativeActivation or UI V1. next_timed_activation returns callback-to-observation timing and, only inside correlated mouse/keyboard pump dispatch, event-to-observation timing. Uncorrelated accessibility callbacks remain None. Correlation is scoped and restored across nested dispatch/unwinding; invalid clocks do not produce a fabricated zero. Mouse-down timing includes hold/tracking until release. Raw uptime is never serialized or logged.

NativeRenderer.frame_progress reports generation-local submitted/completed frame IDs through queue callbacks; counters never wrap or regress. Completion is GPU queue work observed by polling, not compositor presentation or display scanout. The bounded native_meshes probe retains 256 samples/markers, reports overflow and outstanding markers, and correlates actions with the first subsequently submitted frame; intermediate states may coalesce. Presentation-call return and observed completion are separate endpoints. The optional timing profile uses systemUptime for local elapsed time; bundle examples/native-gpu/PrivacyInfo.xcprivacy (reason 35F9.1) with the application according to [Apple's API reasons](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype).

Qualification: Metal, Apple M1, physical 1024×768, 320 instances/2 meshes, pump wait 8 ms. Ten coordinate clicks through native events and ten accessibility activations delivered 20 actions. Native-event p50/p95/p99: action 1.549/19.964/19.964 ms; present-call return 13.326/30.874/30.874 ms; observed GPU completion 23.511/42.509/42.509 ms (n=10). Mixed callback-to-action 2.289/103.954/104.105 ms (n=20); accessibility had no invented event timestamps (uncorrelated=10). All overflow/pending counters were zero; submitted=completed=3435, retained_windows=0. Small-sample results on this profile do not qualify 4K60 or universal input latency.

The source LOD profile supports 1–8 fixed packed triangle ranges and 1–65536 objects. LodView describes a centered perspective camera, physical maximum focal length, viewport half-diagonal upper bound and pixel error budget. Bounds must enclose every level, and geometric_error is a producer-owned conservative deviation from finest geometry. Errors are finite/nondecreasing, finest error is zero, index spans do not overlap, and coarsest stays resident. Orthographic/shifted projection and asset simplification/streaming are not implemented by this selector.

choose_lod is an f64 CPU reference. GpuLodVisibility runs frustum/mask rejection, conservative projected-error selection and per-level compaction in compute. It uses nearest forward depth (including sphere radius/rounding guard), maximum scale, off-axis viewport extent and error-dependent denominator; clipping or near-camera bounds request finest. Missing desired detail selects the next resident coarser level and exposes degradation (choice bit 31); MAX means culled and must be checked first. Residency flags do not retire geometry. The caller retains packed buffers through completion and accounts their payload separately. Visible partitions have 256-byte alignment and each level has a 20-byte indexed-indirect record; selected indices consume no CPU readback in the draw path.

Real Metal tests compare choices/counts/compacted membership with the f64 reference, exercise missing/restored residency, masks, clipping, nonuniform scale, invalid-input preservation, empty reset and byte admission. A separate 512×512 pixel fixture packs a tessellated square, diamond and triangle (24/6/3 indices) into shared buffers and consumes GPU-generated draws in the same encoder. Colors identify levels. Removing/restoring the middle level changes green diamond → blue coarse triangle → green diamond; captured resident/degraded images were inspected. Native visual qualification, offline meshlet/LOD compilation and streaming remain pending.

GpuLodMeshBatch now consumes resolved MeshLodDescriptor assets, packs all levels into shared vertex/index buffers and uses the production pose/color/normal-lighting pipeline. Frames must bind the finest mesh identity and remain opaque/static. A conservative origin-centered model sphere encloses every level and is transformed per instance. Reservation includes packed geometry, poses, camera and LOD selection partitions before upload; byte/device limits fail before allocation. Mesh payload owners remain retained after registry retirement. set_resident changes logical availability only; it does not free packed geometry. A real Metal 512×512 color/depth test verifies poses/material colors, disappearance/reappearance of a diamond-only pixel when middle detail is missing/restored, invalid identity/parameters, budget rejection and empty-frame clearing. This is the reusable production batch; native visual/input/resize qualification remains pending.

GpuMeshScene::new_lod now composes fixed LOD batches through separate prepass/final selection buffers, a shared fresh Hi-Z pyramid and conservative all-level occlusion bounds. encode_lod takes LodSceneFrame with explicit matching matrix/view/groups; using the static encode method for an LOD scene is rejected before writes. Geometry remains duplicated per pass and included in admission. set_lod_resident updates availability consistently in both passes; no packed geometry is evicted. Static scene construction/encoding stays unchanged. NativeRenderer exposes enable_mesh_lods, present_mesh_lods and drained-frame availability changes under existing surface ownership, frame permits, resize peak admission and completion tracking.

native_lod adds 256 refined spheres/octahedron proxies and 64 boxes/tetrahedron proxies, orbit/zoom/pause, pixel budgets 4/12/32/96 and logical Fine on/off. A pure reducer rejects unknown commands; camera-to-projection alignment and bounded controls are tested. Real Metal 512×512 tests with two LOD groups verify detail loss/restoration, empty reset, admission and explicit scene mode. Native process ran to its 180-second deadline: frames=3239, submitted=completed=3239, retained_windows=0. This run had actions=0. SceneWorld now admits a new/reused identity slot in constant time through a preallocated bounded free list instead of scanning all slots. SceneLimits includes four additional payload bytes per identity slot. Reuse order is unspecified; generation exhaustion permanently retires a slot, and invalid/stale/foreign requests cannot add duplicate vacancies or consume one on a failed spawn. The deterministic churn test keeps an owned snapshot while migrating/removing/recreating 4096 entities, checks every live row against a reference, and verifies exact-budget admission and capacity refill. `cargo run -p appcore-render --release --example scene_admission` reports a bounded CPU-only profile (1 warmup + 5 samples for 1024/8192/32768 entities), excluding world/asset allocation, drop and GPU work. It does not qualify GPU frame time or 4K60.

The blocking diagnostic `cargo run -p appcore-render --release --features metal --example gpu_scene_profile` explicitly requires Metal timestamp queries. It profiles the static frustum → Hi-Z → indirect graph with 2048 instances/3072 input triangles in two batches, using an orthographic grid and an empty control at 512×512, 960×540 and 1920×1080. Two warmups precede seven raw CSV samples per case; each includes GPU interval, CPU encoding duration, final indirect counts and admitted payload. Render-pass end markers bracket the graph; the interval includes the ending 1×1 marker. Query resolution is encoded only after host-observed sampling completion; sampling/readback waits each have a five-second deadline. Zero/reversed timestamps or invalid counts fail the run, without filtering or CPU substitution. Uploads, queue delay, readback, display and driver overhead are excluded. This is serialized static offscreen diagnostics, not native input/resize, LOD or continuous-frame/4K60 qualification. The Metal counter lifecycle investigation is recorded in [upstream issue 9414](https://github.com/gfx-rs/wgpu/issues/9414). No dependency patch or version change is required by this profile.

The diagnostic profile also accepts `cargo run -p appcore-render --release --features metal --example gpu_scene_profile -- --lod`. This explicit mode uses a matching 45-degree centered perspective matrix/LodView, near 0.1/far 100, a 32-pixel budget, two batches of 1024 instances and two packed levels (4096 finest/2048 coarsest input triangles). The 0.066 model-space error conservatively exceeds each model’s full bounding-box diagonal. Resident → fine_missing → restored → empty phases each have two warmups and seven measured samples at all three resolutions (84 measured intervals). The readback checks every level’s indexed-indirect record, per-batch capacity, both active levels, zero draws of missing fine geometry, restored counts and empty reset. Logical fallback can exceed the pixel budget and does not evict VRAM. Timestamp/readback/marker payload is 132 bytes in LOD mode (92 for static); color and complete scene reservation are admitted too. Raw output includes per-level counts; static and LOD scenes use different cameras/geometry and are not a speedup comparison. This remains serialized offscreen diagnostics; native LOD visual/input/resize qualification is pending.


NativeRenderer::managed_gpu_bytes reports admitted color, depth and managed scene payload bytes at current dimensions. It is budget accounting, not measured VRAM; driver/compositor/extra swapchain allocations are excluded. Native UI examples expose this value alongside process RSS and camera input; the renderer itself owns neither OS input nor process memory sampling.
